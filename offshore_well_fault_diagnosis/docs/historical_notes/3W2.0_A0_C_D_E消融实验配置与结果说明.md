# 3W 2.0：A0、C、D、E 四组消融实验配置与结果说明

整理日期：2026-11-20。

本文汇总 3W 2.0.0 上现有 A0、C、D、E 四组全量窗口实验。结果以原始 JSON 为准，表格保留四位小数。本次仅整理配置和结果，没有重新训练。

这里的 E 指原始完整 7D 方案，主模型与 chain 预测器统一采用 `weight_decay=1e-5`。它不是后来补跑的 chain 零衰减版本，也不是 1.1.1 数据集上的适配方案。

## 1. 四组实验分别是什么

四组都使用 DVAE 主干和十分类头。区别在于是否把规则证据拼接进分类头，以及是否启用两个辅助 loss。

| 组别 | 模型配置 | 分类头输入 | 规则能量辅助 loss | Chain 辅助 loss |
|---|---|---|---|---|
| A0 | DVAE baseline | 窗口 latent 均值，8 维 | 不启用 | 不启用 |
| C | DVAE + 7D evidence + rule energy loss | latent 均值 + 7D evidence，15 维 | 启用，权重 0.0005 | 不启用 |
| D | DVAE + 7D evidence + chain loss | latent 均值 + 7D evidence，15 维 | 不启用 | 启用，权重 0.001 |
| E | DVAE + 7D evidence + rule energy loss + chain loss | latent 均值 + 7D evidence，15 维 | 启用，权重 0.0005 | 启用，权重 0.001 |

需要区分三个概念：

- **7D evidence 输入**：训练和推理时均计算，作为主分类头的输入。
- **Rule energy loss**：训练时对规则证据进行类别监督，参与更新可学习证据头和相关 DVAE 表征。
- **Chain loss**：训练时增加压力、流量、温度之间的辅助预测任务。

D 组关闭的是 rule energy loss，仍然保留规则证据模块及 7D 分类输入。因此，D 不等于“纯 DVAE + chain loss”。C 也不等于“纯 DVAE + rule energy loss”。

### 2.1 划分单位与预处理

采用固定的 **instance/file-level split**：先划分原始 parquet 实例文件，再在各 split 内生成窗口。同一文件不会分别向训练集和测试集提供窗口。但这不是严格的跨井或跨时间隔离，仍需考虑不同文件来自同井、相近工况的可能性。

窗口标签取有效逐点标签的多数类；101–109 过渡标签映射回 1–9。传感器缺失值在文件内先前向填充、再后向填充；标准化后残留的 NaN/Inf 转为 0，随后将标准化输入截断到 `[-20, 20]`。

归一化统计只从训练文件估计。当前函数默认最多使用 200 个训练文件，每个文件最多抽取 5000 行，并不等于扫描全部训练行计算统计量。该文件内填充流程也不应解释为严格在线、因果的预处理。

四组结果的 `test_split_sha256` 相同：

```text
9e9fdd5a5f66922b9df8fee0b2387e38b784122e49aa301dfdc546be2f57e683
```

该哈希对应排序后的测试文件相对路径清单，不是所有 parquet 内容的校验和。

### 2.2 指标口径

- Macro-P：十个类别 Precision 的等权平均。
- Macro-R：十个类别 Recall 的等权平均；本任务各类均有测试样本，因此等于 Balanced Accuracy。
- Macro-F1：十个类别 F1 的等权平均，不是 Macro-P 与 Macro-R 的调和平均。
- Accuracy：所有测试窗口中预测正确的比例。
- 混淆计数 `i→j`：真实类别为 i、预测类别为 j 的窗口数。

## 3. 模型、7D evidence 和训练损失

### 3.1 分类路径

DVAE posterior 均值记为 `z_mu`，按时间求平均得到 8 维窗口表征。

```text
A0:
  h_cls = mean_t(z_mu)
  logits_cls = classifier(h_cls)

C / D / E:
  x_hat_mu = decoder_mean(z_mu)
  e_rule = f_rule(x, x_hat_mu, z_mu)
  h_cls = concat(mean_t(z_mu), tanh(e_rule))
  logits_cls = classifier(h_cls)
```

其中 `decoder_mean` 是简写，实际 measurement 模块还接收 DVAE 的编码上下文。证据在进入分类头前会进行有限值处理和 `tanh` 变换。四组均不将额外 rule logits 叠加到主分类 logits，`use_rule_energy_logits=false`。

### 3.2 当前 7D 证据

```text
water_rise, water_smooth, dhsv_open_mean, pck_drop,
pck_open_mean, dhsv_low_evidence, pck_low_evidence
```

| 维度 | 计算含义 |
|---|---|
| water_rise | latent 含水代理头输出，经 sigmoid 后，末四分之一均值减首四分之一均值 |
| water_smooth | 同一含水代理序列的一阶差分 RMS，表示粗糙度 |
| dhsv_open_mean | DHSV 有效开度的窗口均值 |
| pck_drop | PCK 有效开度首四分之一均值减末四分之一均值 |
| pck_open_mean | PCK 有效开度的窗口均值 |
| dhsv_low_evidence | `mean(relu(0.85 - a_dhsv))` |
| pck_low_evidence | `mean(relu(0.35 - a_pck))` |

有效开度融合反标准化后的重构开度与 latent 开度头：

```text
alpha = sigmoid(mix_raw)
a_eff = alpha * a_reconstruction + (1 - alpha) * a_latent
```

DHSV 和 PCK 各有一个可学习的标量混合参数，初始 `mix_raw=0`，即 `alpha=0.5`。PCK 的 `ABER-CKP` 重构值先除以 100，再截断到 `[0,1]`；DHSV 的 `ESTADO-DHSV` 重构值直接截断到 `[0,1]`。

这里的含水状态是模型学习的代理量，不是真实含水率测量；有效开度也是模型估计，不能仅凭名称认定其已获得独立物理标定。

相较原 10D 版本，删除了 `dhsv_drop、pck_smooth、dp_trend`。C/D 通过 `RULE_EVIDENCE_KEEP` 指定这七维；原 E 运行通过删除上述三维得到同一顺序的七维。环境变量不完整地记录在旧结果 JSON 中，因此复现还需要参考启动脚本。

### 3.3 四组总损失

```text
L_base = L_rec + 0.001 * L_KL + 2.0 * L_CE

A0: L_total = L_base
C:  L_total = L_base + 0.0005 * L_rule_energy
D:  L_total = L_base + 0.001  * L_chain
E:  L_total = L_base + 0.0005 * L_rule_energy + 0.001 * L_chain
```

A0 与 C/D/E 的 `L_CE` 使用不同的分类输入，前者只接 latent，后者还接 7D evidence。

Rule energy 使用七维证据映射到十类 logits，并计算 CE，温度参数默认 `tau=1.0`。一个需要保留的实现细节是：分类 evidence 使用 posterior 均值对应的重构；辅助 rule loss 在训练代码中重新计算 evidence，传入的是 sampled latent 对应的重构及 `z_mu`。因此两条分支使用同一类证据定义，但数值不必完全相同。

Chain loss 的展开形式为：

```text
L_chain = 0.005 * NLL_flow + 1.0 * NLL_temperature
训练总损失中的对应项 = 0.001 * L_chain
```

| Chain 配置 | 数值 / 内容 |
|---|---|
| history_len | 64 |
| lag | 4 |
| pred_len | 16 |
| hidden_dim | 64 |
| residual_scale | 0.1 |
| dropout | 0.05 |
| flow targets | QGL、QBS |
| temperature targets | T-TPT、T-JUS-CKP、T-MON-CKP、T-PDG |
| pressure inputs | P-PDG、P-TPT、P-MON-SDV-P、P-MON-CKP、P-JUS-CKP、P-JUS-BS、P-ANULAR |
| teacher_forcing | 0.15 |
| chain_use_physical_a | false |

Chain 取历史切片与未来目标切片进行 Gaussian NLL 监督。训练中的 teacher forcing 实际为 `Q_for_temp = 0.15 * Q_target + 0.85 * Q_pred` 的连续混合，不是以 15% 概率随机切换。评估时使用预测流量。

该实现的历史 latent 来自整个窗口的 posterior，因此这里只把它作为辅助训练任务，不据此声称已经完成严格因果的独立未来预测检验。

## 4. 训练配置和实际开关

### 4.1 训练路径

A0 是独立训练的 Stage 1 DVAE baseline。C/D/E 都从 A0 的最佳 checkpoint 初始化，再增加对应模块，全模型微调；不是从上一个消融组逐级继续训练。

| 配置项 | A0 | C | D | E |
|---|---|---|---|---|
| 初始化 | 从头训练 | A0 checkpoint | A0 checkpoint | A0 checkpoint |
| epochs 上限 | 30 | 10 | 10 | 10 |
| patience | 6 | 4 | 4 | 4 |
| lr | 0.001 | 0.0003 | 0.0003 | 0.0003 |
| batch size | 32 | 32 | 32 | 32 |
| zdim / hdim | 8 / 64 | 8 / 64 | 8 / 64 | 8 / 64 |
| beta / cls_weight | 0.001 / 2.0 | 0.001 / 2.0 | 0.001 / 2.0 | 0.001 / 2.0 |
| class_weighting | none | none | none | none |
| 优化器 | Adam | Adam | Adam | Adam |
| L2 / weight_decay | 1e-5 | 1e-5 | 1e-5 | 1e-5 |
| num_workers / cache_size | 4 / 32 | 4 / 32 | 4 / 32 | 4 / 32 |
| pin_memory | true | true | true | true |
| shuffle_windows | false | false | false | false |
| freeze_dvae | false | false | false | false |
| paper_architecture | false | false | false | false |

**`clip_norm=20` 在这个训练器中表示标准化输入截断，不是梯度范数裁剪。**对应代码通过 dataset 执行 `np.clip`；该训练循环未调用梯度裁剪函数。

原始优化器是 `Adam(model.parameters(), lr=args.lr, weight_decay=args.L2)`，没有为 chain 单独分组。因此 D/E 的 chain 参数同样承受 `1e-5` 权重衰减。它与 `chain_prior_weight=0.001` 是不同概念。

| 关键开关 | A0 | C | D | E |
|---|---|---|---|---|
| use_unified_physical_rule | false | true | true | true |
| use_rule_evidence_features | false | true | true | true |
| pinn_weight：JSON 原值 | 0.001 | 0.0005 | 0 | 0.0005 |
| rule loss 是否实际参与训练 | 否 | 是 | 否 | 是 |
| use_chain_prior_aux | false | false | true | true |
| chain_prior_weight | 0 | 0 | 0.001 | 0.001 |
| use_rule_energy_logits | false | false | false | false |

A0 的 JSON 虽保留默认 `pinn_weight=0.001`，但没有启用任何 PINN/rule 模块，所以实际 rule loss 为零。不能只读这个默认数值就认定 A0 使用了物理辅助损失。

四组均未启用 latent physical auxiliary、structured transition 或 boundary loss。C/D/E 的规则模块来自 `10d_dimension_ablation/unified_physical_rule_loss.py`，不是后来 G/H 使用的稳定版平滑度局部实现。

## 7. 关键混淆和结果分析

| 指标 / 错分方向 | A0 | C | D | E |
|---|---:|---:|---:|---:|
| Normal Recall | 0.6934 | 0.7521 | 0.6881 | 0.7176 |
| Class 5 Precision | 0.9808 | 0.9752 | 0.7209 | 0.9787 |
| Class 8 Precision | 0.5701 | 0.6944 | 0.6449 | 0.6387 |
| Class 8 Recall | 0.4482 | 0.4482 | 0.4482 | 0.7980 |
| Normal→8 | 1773 | 1159 | 1474 | 2760 |
| Normal→7 | 1422 | 1007 | 1006 | 1147 |
| 8→Normal | 3485 | 3485 | 0 | 1276 |
| 8→5 | 0 | 0 | 3485 | 0 |

### 7.1 C：加入 7D 和 rule loss 后优于 A0，但水合物召回仍弱

C 的 Macro-F1 从 A0 的 0.8305 升到 0.8609。Class 3 的召回明显提高，Normal Recall 也升到 0.7521。不过 Class 8 Recall 仍为 0.4482，有 3485 个 Class 8 窗口被预测成 Normal。

C 的 Class 8 Precision 在四组中最高，为 0.6944；但高 precision 不代表高 recall，也不能仅凭该指标判定整体最佳。

### 7.2 D：出现明显的 Class 8 向 Class 5 混淆

D 的 Macro-F1 为 0.8571，略低于 C。D 中 `8→Normal` 为零，但新增了 3485 个 `8→5` 错分，Class 8 Recall 仍为 0.4482。因此这并不是识别出了更多 Class 8，而是主要错分去向发生变化。

这些错分也使 Class 5 Precision 降到 0.7209。仅看 Class 5 Recall 会漏掉这个问题，因为它仍然保持 0.9949。

### 7.3 E：完整组合整体最好，但仍有误报代价

E 的 Macro-F1 为 0.9013，优于 C 和 D。Class 7 Recall 达到 1.0000，Class 8 Recall 提高到 0.7980，同时 `8→5=0`。

但 E 的 `Normal→8=2760`，高于另外三组；Class 8 Precision 为 0.6387，Normal Recall 为 0.7176，也不如 C。E 的 Class 9 Recall 降到 0.8749。当前主要问题仍包括正常工况与故障的边界混淆，不能只展示总体提升而省略这些代价。

### 7.4 这四组能回答什么

E-C 和 E-D 分别提供了“保留另一辅助项时，再启用 chain / rule loss”的观察对比。四组结果支持：**在当前开发划分、当前训练配置和 seed42 下，完整组合的分类表现最好。**

但 A0-C 或 A0-D 同时改变了 evidence 输入、辅助 loss 和训练阶段；仅凭这四组不能分离纯 evidence 的独立贡献。需要时应结合已有 B 组，而不是把 A0-C 全部解释为 rule loss 的作用。

## 8. 解释边界与后续诊断

1. **训练预算不完全匹配。** A0 是 Stage 1 结果，C/D/E 额外进行 Stage 2 微调。未完成的 `A_dvae_stage2_budget_control` 不属于本表，不能作为有效的同预算控制组。
2. **只有单个 seed。** 目前不报告四组的均值、标准差或统计显著性，不能声称组合收益已跨随机种子稳定复现。
3. **7D 的选择参考过 test。** 原 E 是维度消融中参考验证及测试表现确定的经验最优候选；不能写成“仅用 validation 选出 7D，再在从未接触的 test 上一次性确认”。
4. **划分不是跨井隔离。** 当前结果反映 fixed instance-level split 的表现，不等于跨井泛化结论。
5. **配置启用不等于预测器已学到有效传播关系。** 后续对原 2.0 E checkpoint 的检查发现，pressure GRU 输入权重范数约 `2.68e-38`，temperature 输出层权重范数约 `3.16e-38`，已接近零。因此不能仅凭 E 优于 C/D 就断言 chain 预测器保持了有效的物理传播建模能力，或声称已证实某种“协同稳定机制”。
6. **单独取消 chain 衰减没有直接改善分类。** 后续 2.0 补跑保留完整方案，仅将 chain 参数的 weight decay 改为 0，测试 Macro-F1 为 0.8532、`8→5=3485`；其流量 MSE 虽由约 0.2884 降至 0.0491，分类结果却下降。这是另外一组实验，不替换本表中的 E，也说明预测任务改善不必然转化为分类收益。

上述第 5、6 点是对主结果解释的补充，不改变 A0/C/D/E 已记录的数值。它们要求在论文里区分性能观察和机制证明。

## 10. 当前可采用的结论

在 3W 2.0.0 的 fixed instance-level full split 和 seed42 下，A0、C、D、E 的测试 Macro-F1 分别为 0.8305、0.8609、0.8571、0.9013。完整 E 在这四组中整体最好，并改善了 Class 7/8 的召回及 D 中的 Class 8→5 混淆；但 Normal 误报、Class 9 召回下降等问题仍然存在。

现阶段应把它写成已记录的探索性消融结果。相对 A0 的提高包含微调阶段和训练预算的贡献；E-C/E-D 提供组合配置的观察证据，但单 seed、test-informed 方案选择及预测器权重退化等因素，限制了对模块独立因果作用和物理机制的进一步推断。
